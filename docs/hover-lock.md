# 悬浮锁：macOS / Windows

鼠标在可视化窗口范围内连续停留 3 秒后，中心偏上显示小型手绘锁按钮。点开锁后可拖动画面移动、拖动右下角等比缩放；再次点锁保存几何位置并恢复穿透。离开画面即隐藏按钮，下次进入重新计时。菜单栏 / 托盘的调整入口继续有效，与按钮使用同一调整状态。锁定状态不是新的持久化偏好；启动时仍默认穿透，位置与尺寸仍按可视化模式保存。

## 实现边界

- 使用被动鼠标位置采样，不创建全桌面点击层、不截屏、不增加键盘监听，不为此功能请求辅助功能或输入监控权限。
- macOS 使用小型非激活子 `NSPanel`，Windows 使用小型非激活 owned WPF window。锁定时主画布始终穿透，仅可见小锁的按钮范围接收鼠标。
- 按钮随画布位置、大小与显示器缩放更新；切换模式、隐藏或显示器重配置会清除旧悬浮等待。
- 显示按钮与锁状态独立，点击开锁/上锁无需重新等待，避免按钮跳闪。

## 验证

自动检查涵盖连续停留、离开重计时、反复切换、隐藏清理、窗口穿透属性、原有尺寸/位置保存，以及手绘图标渲染。Windows 可移植测试和交叉编译可在 Linux 上执行；AppKit 和 WPF 原生检查在各自 GitHub Actions runner 上执行。图标使用离屏渲染检查；窗口级检查短暂显示合成窗口并注入测试时间/内部点击事件，不移动真实鼠标、不读取个人输入。此类检查不等于跨应用桌面交互验收。

双端实机仍应检查：

1. 在下层普通应用上方停留不足 3 秒，再移出/返回；只在新的完整等待后出现锁。
2. 锁定时点击画面不同位置，下层应用正常响应；仅小锁按钮截获点击，不改变前台应用焦点。
3. 连续开锁/上锁 20 次，拖动、右下角缩放，菜单状态始终同步，无残留鼠标捕获。
4. 切换飞鸟/五线谱，隐藏/恢复、睡眠/唤醒，按钮无残留，位置尺寸仍分别保存。
5. 混合 DPI、多屏负坐标、跨屏拖动、拔除副屏、修改分辨率，锁始终位于画面中心偏上。

验收只使用合成输入；不上传个人桌面、真实音频或键盘内容。
