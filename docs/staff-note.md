# 五线谱音符

`staff-note` 是第二个内置可视化模块，菜单名为「五线谱音符」。它直接消费现有进程内特征通道，不改动音频算法或音频 JSON 契约。Windows 仍处于规划状态，接入职责见[绘制入口](../modules/visualizations/staff-note/platforms/windows/README.md)。

## 画面与音乐映射

基准画面 800 × 160，5:1 比例；宽度范围 600～1600 点，同时受屏幕可见区域限制。实心符头中心固定在 x=640，作为符干和符尾左右倾摆的支点。透明、无边框、鼠标穿透；默认石墨灰，菜单可选择[公共五种笔色](appearance.md)，保留浅色衬线，笔迹的弯曲与排线位置固定。

固定高音谱号和 8 点线距，中线 B4 位于 y=74；五条线是 y=58、66、74、82、90。相邻自然音相隔 4 点，八度相隔 28 点。半音统一采用升号拼写，C4/C♯4 同谱位、由 ♯ 区分。低音 E2 位于 y=146，高音 C7 位于 y=14；超出五线谱补加线。这里的 y 向下增加。

| 特征 | 表现与限制 |
| --- | --- |
| 主旋律音高 | 置信度至少 0.48，半音量化并保留 15 音分边界滞回；半音/全音立即更新，较大变化经短时连续确认后更新目标，临界阻尼弹簧约 150ms 收稳 |
| 起音事件 | 角速度脉冲触发符干和符尾绕实心符头中心左右倾摆，连续起音交替施力，角度连续；每侧最多倾斜 20°，约半秒一个回摆周期，阻尼振荡后回正；力度随音量包络和起音强度增加，符头中心保持准确谱位，符头形状、升号、加线和音名不随倾摆旋转 |
| 音量包络 | 按当前乐段的短时分贝范围增强缩放对比，围绕符头中心平滑缩放至约 0.8～1.5 倍，静音回到 0.94 倍；范围向外立即扩张、向内以 3 秒时间常数收敛，最小动态跨度 12dB，稳定长音保持稳定；原始音量包络仍增强起音摆动力度，准确谱位与轨迹不受缩放影响 |
| 可靠旋律历史 | 保留过滤后音名及真实谱位，线条使用 25ms 时间常数轻度平滑；向左每秒移动 70 点、线性淡出，最多 8 秒/512 点 |
| 缺失或过期旋律 | 未检出立即分段；缓存或未确认候选不能延长旧音高的 240ms 有效期；保持最后目标高度，音名淡为 `—`，不追加轨迹；有声音时仍可响应新起音 |
| 静音、失联或过期音频 | 停止新倾摆，已有角度平滑回正；已有轨迹自然移动、过期 |

首次没有旋律时，在中线以低透明度待机。旋律中断前后的轨迹分段，避免连接无关音高。帧龄达 400ms 视为过期音频；重连、格式变化、PCM 时间线重置及隐藏恢复清理旧输入历史。新模块或恢复显示使用新通道订阅，旧起音不补播。

造型固定为普通八分音符；不根据音乐推断时值、调号、拍号或和弦，不生成完整乐谱。新模式不显示飞鸟的管道、计分、云朵、气团或调色界面。

## 短时毛刺过滤

`StaffPitchTracker` 只在五线谱模块中处理音高候选。首次可靠音高和中断后的首音立即采用；相对于当前音高，变化不超过 2 半音时立即响应，保留正常人声的小幅换音和滑音。

| 变化幅度 | 连续确认要求 | 48kHz / 1024 样本步长下的合成输入实测 |
| --- | --- | --- |
| 3～5 半音 | 至少 2 个新结果，跨度至少 20ms | 约 21ms |
| 6～10 半音 | 至少 3 个新结果，跨度至少 40ms | 约 43ms |
| 至少 11 半音 | 至少 4 个新结果，跨度至少 60ms | 约 64ms |

确认使用音频时间戳；重复快照不计数，结果间隔超过 75ms 时重新确认。待确认音高允许在最初候选附近上下 1 半音变化，远处的新候选重新计数。短暂偏离又返回原旋律会被丢弃；确认期间音符和轨迹保持上一个可靠音高，起音仍可立即触发左右摆动。未确认候选不会刷新旧音高的有效期；静音、缺失、失联、格式变化和隐藏恢复均清理待确认状态。

轨迹单独按音频时间间隔做 25ms 的指数平滑，不包含音符本体的摆动、缩放或运动惯性。新段从真实谱位开始；持续音最终回到真实高度，保留八度距离。上述确认耗时从首个新候选算起，不包括采集、音高分析和显示延迟；显示漏帧时还可能更长。

本规则抑制短暂误选，不识别人声身份。持续占优的伴奏仍可能被确认，很短的真实大跳也可能被过滤。回归使用合成音高序列，包括高置信度的一两帧伴奏式插入、快速乐句、真实持续大跳、重复/稀疏输入、过期与断续音高，并检查正常小幅变化在首帧响应。结果和各跳跃确认耗时见 [staff-note-tests.json](validation/staff-note-tests.json)。

## 窗口与生命周期

飞鸟和五线谱分别保存位置、大小；应用记住上次选择，未知 ID 回退飞鸟。飞鸟继续读写原偏好键。切换先保存、暂停刷新，替换会话后恢复布局，再激活；音频连接不重启。首次切换保持左上角锚点，超出屏幕时回到可见区域。

## 绘制缓存与慢帧检查

原生窗口使用保留的矢量图层绘制五线谱、音符和轨迹；显示刷新只提交轨迹路径、位置、缩放和倾摆角度，音名变化时更新独立文字图层，减少整块画布重绘和位图提交等待。离线导出继续使用相同几何路径的 Core Graphics 参考绘制；平台验证覆盖原生图层的符头支点、旋转和五色透明输出。

符头、两种符干方向、升号、排线和各谱位加线复用固定路径。全部 E2～C7 音名及待机横线在视图创建时准备文字样式和离线 Core Text 排版，换色时重建文字缓存。

音频看门狗在持续收到新 PCM 时直接判定采集健康；需要核对输出设备状态时，在后台执行 Core Audio 查询，返回后复核采集代次和取消状态。这样设备探测的同步系统调用不会阻塞界面刷新，旧探测结果也不会影响重连后的采集。

原生刷新测量可指定窗口宽度和测量秒数，例如 `zsh scripts/measure-performance.sh --staff-cadence build/staff-cadence.json 640 15`。默认仍为 1000 点宽、测量 6 秒；先预热 1 秒，再记录刷新间隔、CPU 绘制或图层提交耗时、超过 25ms 的间隔及相邻两帧耗时，并验证隐藏停止刷新和恢复显示。CPU 耗时不包含 WindowServer 的实际显示耗时。测试使用合成特征和真实透明窗口，需保持桌面解锁、显示器唤醒；测量应与编译分开执行。

2026-10-23 对照测量中，640 点窗口的 15 秒刷新平均约 60fps，最长间隔从 61.29ms 降至 29.74ms；最终仍有 4 个超过 25ms 的间隔。1000 点窗口的 6 秒测量最长间隔从 49.69ms 降至 28.14ms。顺序测量受系统负载影响，不能据此保证所有场景无掉帧。各阶段数据、验证结果和对应源码哈希见 [staff-render-performance.json](validation/staff-render-performance.json)。

## 新增模块时的验证记录

```sh
zsh scripts/test-staff-note.sh
zsh scripts/test-staff-note-platform.sh
zsh scripts/test-contracts.sh
zsh scripts/test-visualization-host.sh
zsh build.sh
dist/Miucs.app/Contents/MacOS/Miucs --render-staff-preview --output build/staff-note-preview
zsh scripts/measure-performance.sh --staff-cadence build/staff-note-cadence.json
```

规则结果见 [staff-note-tests.json](validation/staff-note-tests.json)，原生布局与绘图结果见 [staff-note-platform-tests.json](validation/staff-note-platform-tests.json)。测试仅使用合成音高与独立偏好域。合成预览覆盖 600/800/1600 点、透明/浅色/深色背景、E2/C7 边界与待机，重复静帧按像素检查笔迹稳定。

首次接入时共 206 项自动检查通过，独立 NumPy 参考 542 窗口无差异，飞鸟三张静帧与改动前字节完全相同。当时的构建和严格签名校验通过。解锁后原生刷新实测：五线谱约 59.5 fps，绘制 p95 为 0.43ms；飞鸟回归约 59.7 fps。两者隐藏后停止绘制，恢复显示后一秒均绘制 57 帧。测量使用 1000 点宽的真实透明窗口，6 秒内分别出现 1 次和 2 次超过 25ms 的刷新间隔，不代表长期无卡顿保证；源码哈希和性能记录对应首次接入版本。

原生应用已观察到从飞鸟切到五线谱的画面变化，并在新构建重启后恢复五线谱选择、位置与 800 × 160 尺寸；飞鸟原有位置和大小保持不变。修复了应用菜单未随模块刷新设置项的问题，五线谱下设置入口已正确禁用。缩放边界和模块切换生命周期由原生平台测试覆盖。汇总与对应源码哈希见 [staff-note-validation.json](validation/staff-note-validation.json)，详细刷新数据见 [五线谱](validation/staff-note-cadence.json)与[飞鸟回归](validation/flight-cadence-staff-regression.json)。

原生 cadence 测量使用合成采集传输和真实透明窗口，需要显示器唤醒且桌面解锁；不捕获真实声音或屏幕。位图绘制耗时不代表原生呈现帧率。原有飞鸟绘制保持不变，回归对照使用同一合成场景。
