# Miucs 音频特征与验证记录

更新日期：2026-10-22。本文记录基础音频分析的先行验证阶段。

后续更新：已实现铅笔音乐飞鸟，以及独立的主旋律近似提取。本文保留基础测量验证记录；最新状态、主旋律准确率与限制见 [飞鸟实现记录](sound-flight.md)。

## 目标与边界

输入为系统播放的原始 PCM 音频。先建立可解释、可复现的特征提取层，再把经过验证的特征交给视觉层。数字信号强度不等于环境声压；低/中/高频不直接等于鼓/人声/镲；起音不等于节拍；声道关系不等于真实空间位置。

验证分为三个层次，不能相互替代：

1. 已知信号验证：用频率、幅度、声道关系、事件时间已知的音频检查算法数值。
2. 输入链路验证：检查交错/非交错 PCM 解码、不同采样率和分块方式是否产生相同结果。
3. 实际系统采集验证：将测试音通过系统播放并重新采集，检查系统增益、时延、声道与实际输出。音乐听感和主观视觉映射另行评估。

| 强度 | 静音、静音持续时间 | 基于原始 dBFS、迟滞阈值与静音保持时间 | 绝对静音、阈值附近防抖、短暂间隙 | 实现并验证 |
| 频谱 | 低/中/高频能量与占比 | 在原始线性功率谱中积分，不对显示柱求和 | 单频归属、混合音能量比例、边界误差 | 实现并验证 |

| 频谱 | 频谱平坦度 | 功率谱几何均值 / 算术均值 | 正弦较低、白噪声较高；静音无有效值 | 实现并验证 |
| 频谱 | 频谱变化、起音强度 | 相邻帧压缩振幅谱的正向差分 | 静稳音不连续触发；鼓点时间与误报 | 实现并验证 |

## 现有代码审查

开始本阶段时：

- `level` 是 RMS ×4 后限幅至 0…1，再平滑的显示值，不是原始 RMS 或标准响度。
- 24 段频谱取频段内峰值，再做分贝与显示映射，不能直接相加当作能量占比。
- 分析前将左右声道平均，反相信号会抵消，且无法继续提取立体声特征。
- FFT 固定按 48 kHz 换算频率，应依据输入的实际采样率处理。
- 原频谱每个输入回调仅计算一帧，输入分块较大时会积压或跳过数据；需用固定窗口与步长处理完整数据。
- 原平滑系数按回调次数计算，输入分块变化会改变实际时间响应。

## 实现约定与验证结果

结论：本阶段的基础特征在受控信号、独立数值参考与实际系统回放链路上通过验证，可以供 UI 使用。后续新增的主旋律近似已单独评估，准确率与限制见飞鸟实现记录；BPM、人声识别等仍待实现和验证。起音检测目前是规则算法，测试通过不代表在所有音乐上都能准确判断事件。

### 数据接口与定义

`modules/audio/core/` 中的分析器负责流式分析，`platforms/macos/AudioPCMDecoder.swift` 保留双声道解码。当前原始特征和独立主旋律经 `FeatureChannel` 的内存快照、事件和区间峰值交给可视化，不再逐帧通过 Combine 发布。旧版派生的 `level`、`bands` 已移除；`displayBands` 仍保留在数据契约中。分层与跨平台入口见 [架构说明](architecture.md)，字段定义见 [音频契约](../contracts/audio-features/README.md)。

- 窗口为 2048 样本，步长 1024 样本，周期 Hann 窗。在 48 kHz 下，窗口覆盖约 42.67 ms，输出间隔约 21.33 ms；这不代表总采集或显示延迟。
- 频率依据输入的实际采样率换算。格式变化会重置缓冲、时间线和历史状态。每次输入处理全部可用窗口，保留不足一窗的尾部。
- `time` 是分析窗口中心相对本次音频序列的秒数。没有拿到音频缓冲时不凭空生成静音帧；连接状态与静音状态应分别处理。
- `rms` 为所有声道原始样本的均方根；`peak` 为绝对峰值；`rmsDBFS = 20 log10(rms)`，静音数值下限 -240 dBFS。浮点 PCM 超过 ±1 时测量不截断。不等同于 LUFS、扬声器音量或环境声压。
- `envelope` 单独按时间平滑，攻击时间常数 25 ms、释放时间常数 200 ms。显示层的增益不反馈到测量层。
- 静音进入阈值 -60 dBFS，需连续保持 150 ms；退出阈值 -54 dBFS。`silenceDuration` 表示连续低于进入阈值的观察时长。首次连接默认静音，跨越退出阈值后激活。
- 频谱先分别计算各声道功率，再取平均，避免反相信号被平均抵消。频谱分析去除直流，原始 RMS 保留直流。
- `lowEnergy`：20…250 Hz，`midEnergy`：250…4000 Hz，`highEnergy`：4000…20000 Hz，均为线性功率。下边界包含、上边界不包含，最高上界按 Nyquist 限制并包含端点。频点按中心频率归属。`*Share` 的分母仅为这三个频段的功率和。
- 重心与带宽采用振幅谱权重。为避免 Float32 FFT 舍入噪声抬高纯音的带宽，频谱矩与变化量忽略低于最大功率 120 dB 的频点；原始频段功率不受这个处理影响。
- 平坦度使用 20 Hz…20 kHz 范围内功率谱的几何均值/算术均值。频谱有效性要求 RMS > -100 dBFS 且该频域内功率 > 1e-12。平坦度不是噪声类别概率：带限噪声的全带平坦度也可能很低。
- `spectralFlux` 为相邻帧振幅谱正向差之和/当前振幅谱之和，范围 0…1。起音门限为最近约 1 秒变化量的中位数 + 4 倍稳健标准差（1.4826×MAD），下限 0.18；设置 100 ms 不应期。第一帧只初始化历史，不推断此前是否有起音。它不是拍点、鼓点或 BPM。
- `balance` 为能量平衡，-1 左、+1 右。`sideEnergyRatio` 为 Side/(Mid+Side) 能量比；单边声道也会得到 0.5，因此不能脱离平衡、相关性单独解读为“听感宽度”。
- `correlation` 为去直流后的左右相关系数。静音、单声道、某侧无有效变化时，相关性没有定义。不可用值使用 Optional（JSON 中省略），不伪造为 0。
- 当前输入支持等长单/双声道、原生字节序紧密排列 Float32 PCM，验证了交错/非交错两种布局；不支持的格式明确拒绝。
- 24 段显示柱依旧保留。2048 点 FFT 在 48 kHz 下频点间隔约 23.44 Hz，最低几个显示段可能共享频点；它们不是 24 个完全独立的测量频带。频带边界附近有窗函数泄漏，不能按一个尖锐频率边界判断乐器。

### 验证证据

| 层次 | 结果 | 说明 | 记录 |
| --- | --- | --- | --- |
| 已知信号与输入链路 | 28/28 通过 | 音量、分频比例、频谱矩、平坦度、声道、静音、起音、分块一致性、采样率、PCM 布局和异常输入 | [详细结果](validation/audio-feature-tests.json) |
| 独立 NumPy 参考 | 542 个窗口全部通过，0 个比较超差 | 用 Float64 `numpy.fft.rfft` 从 WAV 原始采样重新计算 16 个测量字段，包含段落切换边缘 | [详细结果](validation/numpy-reference.json) |
| 系统播放与采集 | 12/12 片段通过 | 排除已有应用后，回放已知测试音；检查纯音、频段、左右声道、反相、带限噪声和静音 | [详细结果](validation/system-audio.json) |

关键受控结果：

- 幅度 0.5 的正弦 RMS 为 0.353553384，理论值为 0.353553391；幅度减半下降 6.020599913 dB。
- 低/中/高三音混合的幅度比例为 0.3/0.2/0.1，提取能量占比分别约 0.642857/0.285714/0.071429，符合幅度平方比例。
- 同相/反相的声道相关性分别为 +1/-1；反相情况下频谱仍正确保留；单边静音的相关性不输出数值。
- 未带限白噪声的单声道平均平坦度约 0.562，纯音接近 0。
- 8 个已知起音全部检出，最大窗口中心时间戳偏差约 18.67 ms，无额外事件。这不是端到端延迟测量。
- 稳定正弦无重复起音；固定种子的 6 秒白噪声在首秒热身后没有起音误报。自然音乐仍需单独测精确率/召回率。
- 44.1 kHz、48 kHz、96 kHz 的测试均通过；输入块大小变化时，输出帧数与所有测量逐项一致。
- 独立参考的重心最大误差约 0.0011 Hz、带宽最大误差约 0.008 Hz、频段占比最大误差 < 1e-8。该误差指与数值参考的符合程度，不代表真实音高精度。

### 实测过程中发现的问题

1. 第一次系统回放混入其他正在播放的音频，不能对原测试文件作逐值判断。诊断模式改为排除启动前可枚举的应用，再启动测试播放器；正常拾音仍使用系统混音。静音片段用于检查排除是否有效。
2. Float32 FFT 在强纯音以外产生的微小舍入噪声，会被带宽的二阶矩放大；独立参考曾发现约 3 Hz 偏差。增加明确的数值底限后，误差降到约 0.008 Hz 以内。
3. 早期起音门限在稳定白噪声中产生 2 次误报。提高稳健门限后，相同测试误报为 0，8 个已知起音仍全部检出。不能据此声称适用于所有自然音频。
4. 原宽带噪声回放的 RMS 为约 0.040912，文件值约 0.046276；纯音与声道项通过。运行时默认输出为 44.1 kHz，采集为 48 kHz，输出通路的带宽/转换可能解释差异，但未把它当作已证明的根因。此轮失败保存在 [宽带回放记录](validation/system-audio-wideband.json)。后续用 8 kHz 低通噪声排除通路超高频差异，在相同严格 RMS 容差下通过。纯数字全带噪声仍由已知信号与独立参考覆盖。
5. `afplay` 进程启动到实际出声有启动延迟。系统验证按第一段已知低频音对齐，再检查其他片段内部，避免把进程启动时间误作采样起点；未声称已测得端到端延迟。

### 复现

环境：Apple Silicon macOS、Swift 6 编译；独立参考需要 Python 3、NumPy 和 SciPy。输出 JSON 会被同名新报告替换。

仅运行数值验证，不播放声音：

```sh
zsh scripts/validate-audio.sh
```

连同实际系统播放/采集验证（会播放约 12 秒低幅度测试音，需要现有系统音频捕获授权）：

```sh
zsh scripts/validate-audio.sh --live
```

分析任意本地音频文件，便于后续挑选真实音乐与语音做评估：

```sh
zsh scripts/analyze-audio-file.sh /absolute/path/input.wav /absolute/path/features.json
```

报告保存在 `docs/validation/`。生成的测试 WAV、逐帧诊断数值与临时可执行文件位于忽略的 `build/`；报告记录输入文件与分析器的 SHA-256。诊断不保存实际采集的 PCM 或屏幕画面，也不更改系统输出设备、音量或其他播放器状态。

### 后续 UI 可使用的边界

可以使用原始能量、分频能量、包络、频谱重心/带宽/平坦度、声道关系和静音来设计连续动效。起音适合做触发效果，并保留误判回退。后续的独立主旋律近似已接入飞鸟，见上述实现记录；BPM/拍相位、语音/乐器类别、情绪等仍未实现。
